# 当前骨架说明

现在跑起来的是文献引路的空壳。它能启动，能告诉你自己和数据库是否还活着，并给出两个还没有功能的页面。上传论文、检索、登录和提问都还没有。

## 现在能干什么

一条命令会同时启动三个进程：数据库、应用、伴随进程。

- 打开 http://localhost:8000/ 能看到「文献引路」，以及通往文献库、阅读助手的链接。
- http://localhost:8000/library 和 http://localhost:8000/reader 只显示空状态。没有上传文件的控件，也没有提问框。
- http://localhost:8000/health 不需要登录。数据库连通时返回 HTTP 200，并写明应用和数据库都是 `up`。数据库连不上时应用仍在，这个地址返回 HTTP 503，数据库为 `down`。
- http://localhost:8001/health 是伴随进程的存活检查。它不连数据库。其它路径返回 404。
- 缺少 `DATABASE_URL` 时，应用在开始接受请求之前退出。对话和嵌入的密钥可以先空着。
- 每个 HTTP 请求在标准输出留下一行 JSON，里面的 `request_id` 与响应头 `X-Request-Id` 相同。
- 数据库第一次启动时会创建 `vector` 扩展。还没有文献表，也没有片段表。

## 一次请求怎么走

浏览器访问 8000 端口，进入应用进程。`/health` 由接口层接到业务层，业务层再请数据访问层对数据库执行 `SELECT 1`。其它页面地址返回已经构建好的前端页面。8001 端口是另一个进程，只回答自己是否在运行。

## 代码在哪里

### 根目录

| 文件 | 作用 |
| --- | --- |
| `README.md` | 一句话定位，以及本机启动和测试命令 |
| `AGENTS.md` | 每次会话都要遵守的三条安全约束；提交检查指到技能 |
| `docker-compose.yml` | 同时启动数据库、应用、伴随进程，并公布 8000 和 8001 |
| `.env.example` | 只列出要填写的键名，没有真实口令 |
| `.env` | 本机真实配置。不入库 |
| `.gitignore` | 不提交 `.env`、虚拟环境、`node_modules`、构建产物和测试报告 |
| `.dockerignore` | 构建镜像时不把上述本地目录打进去 |
| `pyproject.toml` | 告诉 pytest 去 `backend` 找代码、去 `tests` 找测试 |

### `backend/`：8000 端口的应用

| 文件 | 作用 |
| --- | --- |
| `Dockerfile` | 先构建前端，再装 Python 依赖，最后用 uvicorn 启动 |
| `requirements.txt` | 应用要安装的 Python 包 |
| `app/__init__.py` | 标明这是一个 Python 包 |
| `app/main.py` | 组装应用：检查配置、登记路由、写访问日志、托管页面 |
| `app/config.py` | 读取 `DATABASE_URL`。没有就退出 |
| `app/api/health.py` | `GET /health`。不写 SQL |
| `app/services/health.py` | 把数据库检查结果组成响应 |
| `app/db/ping.py` | 对数据库执行 `SELECT 1`，超时 2 秒 |

各层的 `__init__.py` 只为了让目录成为包。

### `companion/`：8001 端口的伴随进程

| 文件 | 作用 |
| --- | --- |
| `Dockerfile` | 只安装这个进程自己的依赖并启动 |
| `requirements.txt` | 它用到的 Python 包 |
| `app/main.py` | 只提供 `GET /health`。不读 `DATABASE_URL` |

以后的 arXiv 工具会放在这里。现在没有。

### `db/`

`db/init/01-vector.sql` 在数据库第一次启动时执行，创建 `vector` 扩展。

### `frontend/`：页面

| 文件 | 作用 |
| --- | --- |
| `package.json` | 前端依赖，以及构建、测试命令 |
| `package-lock.json` | 锁定依赖版本，让镜像里的安装可重复 |
| `index.html` | 浏览器最先拿到的页面，里面已有产品名和两个入口 |
| `vite.config.ts` | Vite 的构建和组件测试配置 |
| `tsconfig.json` | TypeScript 编译选项 |
| `src/main.tsx` | 把页面挂到浏览器 |
| `src/App.tsx` | 标题、两个链接，以及 `/library`、`/reader` 两条路由 |
| `src/pages/LibraryPage.tsx` | 文献库的空状态 |
| `src/pages/ReaderPage.tsx` | 阅读助手的空状态 |
| `src/App.test.tsx` | 检查这两个页面是空的，且没有上传和提问控件 |

`node_modules/` 和 `frontend/dist/` 是安装和构建生成的，不入库。镜像里用的是构建出来的 `dist`。

### `tests/`：pytest

| 位置 | 作用 |
| --- | --- |
| `normal/` | 正常路径：能启动、健康检查成功、日志、页面文字、伴随进程存活 |
| `failure/` | 失败路径：缺配置、数据库不可达、未知接口、伴随进程的其它路径 |
| `boundary/` | 响应和日志里不出现口令和网关密钥 |
| `companion_loader.py` | 单独加载伴随进程，避免它和应用都叫 `app` 而冲突 |

报告写到 `test-reports/`，该目录不入库。

命令在 `.cursor/commands/`，要用时以 `/` 调用，例如 `/opsx-apply`。
