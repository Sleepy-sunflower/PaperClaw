# 文献引路：学期项目说明

课程：互联网软件开发技术与实践  
选题类型：自选课题（待教师确认）  
完成方式：一人项目，兼任规约、开发与验收三个角色

## 1. 项目题目

**文献引路**

面向个人研究的文献阅读助手。用户上传自己的论文，向阅读助手提问。助手只依据该用户的文献库和本次检索到的出处回答，并按阅读引导技能帮助读者看清主张、证据和局限，而不是替读者下结论。需要查找新文献时，助手通过 MCP 调用 arXiv 检索，把外部结果与本地出处分开呈现。

## 2. 主要功能

五个功能分别对应课程要求的知识库、大语言模型、智能体、技能和 MCP。

| 功能 | 说明 | 对应要求 |
| --- | --- | --- |
| 个人文献库 | 注册登录后上传 PDF。每份文献只属于上传者，他人不可见、不可检索 | 知识库、权限 |
| 可追溯检索 | 在本人文献库中做关键词检索和向量检索。每条结果包含文件名、页码和原文片段 | 知识库 |
| 阅读助手 | 针对一篇文献或整个个人文献库提问。回答以流式逐段显示，并列出所用片段 | 智能体、大语言模型 |
| 阅读引导技能 | 技能正文约束回答方式：先定位主张、证据和局限，不直接替读者撰写结论 | 技能 |
| 文献检索工具 | 阅读助手通过 MCP 发现并调用 arXiv 检索。外部论文的题名、作者和摘要与本地片段一并用于本次回答，页面上标为「外部文献」 | MCP |

第一版明确不做以下事项，以保证一人可完成、可演示：

- 不做班级、作业布置、提交和批改。
- 不做多轮对话记忆。每次提问只携带本次问题和本次检索结果。
- 只接收 PDF。
- MCP 只提供两个工具：按关键词检索 arXiv，按论文标识获取摘要。不做全量爬取，不做引用图谱。

验收时除主路径外，还要能演示这些失败情况：未登录请求被拒绝；不能看到或检索他人文献；文献库中没有相关内容时不调用对话模型，并回答「资料里没有相关内容」；arXiv 调用失败时明确报告失败，而不把失败说成资料里没有内容。

## 3. 技术方案

新建独立仓库。认证、文档切块、向量入库、检索和流式回答沿用 CampusClaw 中已经验证的实现路径；业务边界由「班级」改为「个人文献库」，每条文献记录归属上传者。

- **前端**：React 与 Vite。两个页面：文献库（上传、列表、检索），阅读助手（选择提问范围、提交问题、流式显示回答、展示出处）。
- **后端**：FastAPI。身份认证使用 Bearer token，密码以 Argon2 哈希保存。文献、片段和会话的查询都限定为当前用户。
- **知识库**：PostgreSQL 与 pgvector。PDF 按页抽取正文，以 400 字为窗口、80 字重叠切块，调用课程网关的嵌入接口得到 2048 维向量。检索使用余弦距离，距离不超过 0.70，最多返回 5 条。
- **智能体与技能**：分表存放。智能体保存角色提示词，例如「你是文献阅读助手」。技能保存阅读引导正文。一次提问拼成一次对话请求：系统消息为角色提示词与技能正文，用户消息为本次问题及命中片段。回答使用流式返回，`max_tokens` 为 512。对话地址、密钥和模型名只存在于服务端环境变量，不进入页面和接口响应。
- **MCP**：单独提供一个小型 MCP 服务，工具为 `arxiv_search` 与 `arxiv_get`。文献引路后端作为主机，启动时发现工具，将工具绑定到阅读助手，调用时进行鉴权。arXiv 结果与本地片段一起放入同一次回答，并在页面上与本地出处区分。
- **部署**：Docker Compose 启动数据库、应用接口和 MCP 服务。前端构建产物由应用接口一并提供，一条命令可以启动可演示环境。
- **规约**：使用 OpenSpec。每个功能先完成提案、规格、设计与任务，再按规格中的场景编写测试。

实施顺序如下。前一步可以演示后，再开始下一步。

1. 登录、上传 PDF、切块并写入向量。
2. 关键词检索与向量检索，结果可回溯到原文和页码。
3. 阅读助手：角色提示词、阅读引导技能、流式回答；没有命中时不调用对话模型。
4. MCP：工具发现、绑定与鉴权调用，使 arXiv 结果进入同一次回答。
5. 自动化测试、容器化部署，以及答辩用的演示数据（3 至 5 篇真实在读的 PDF）。

PDF 入库改为异步任务不列入第一版承诺。前四步完成且仍有余量时，再作为后续增强。

## 4. 小组成员及分工

成员一人。课程规定的三个角色由同一人按顺序担任，不并行混淆。个人贡献记录中写明兼任关系。

| 角色 | 产出 |
| --- | --- |
| 制定规约 | 每个功能一份 OpenSpec：谁可以使用、做什么、不做什么、失败时如何响应、以什么测试作为证据 |
| 开发系统 | 按任务清单实现。主路径在开发过程中保持可由 Docker Compose 启动 |
| 项目验收 | 用同一份规格中的场景运行测试，并保留演示清单：登录、上传、检索、流式问答、出处、无命中、越权访问、MCP 调用成功与失败 |

贡献记录说明：全组仅一名成员，三个角色均由本人按「先写规约、再实现、再对照规约验收」的顺序完成。记录附上每份规格、对应提交和测试结果。
